# TPS–TOPAS Carbon-Ion PBS QA

This project reconstructs a TPS-exported carbon-ion PBS QA plan in TOPAS and compares the TPS physical-plan dose with TOPAS `DoseToMedium`. Commissioned runs use an independent machine-bound particle-number scale, `N_plan/N_sim × C_machine`, derived from RTPLAN meterset, the selected treatment machine's commissioned number-per-MU table and its audited output correction (`C_machine=1` for the current profile; no empirical correction); TPS dose is never used to fit MC output. The clickable GUI runs only on `127.0.0.1`; no DICOM or dose data is uploaded.

Start the GUI by double-clicking [Launch TPS-TOPAS GUI.command](./Launch%20TPS-TOPAS%20GUI.command), or run:

```bash
./.venv/bin/python launch_gui.py
```

The GUI provides separate click-to-import controls for CT, RTPLAN, RTDOSE and RTSTRUCT, automatic previous-patient setting/result caching, a non-destructive `Reset defaults` control, selectable TOPAS histories/thread plans with runtime estimates and automatic re-preflight, clickable RTPLAN energy-layer selection, and an audited choice between RTPLAN Energy/spots and a manually defined single Energy/spot research beam. Its persistent batch queue can choose/create each case folder and import CT, RTPLAN, RTDOSE and RTSTRUCT independently without changing the Workflow case. It accepts any number of completed cases, runs one or two locally, starts the next waiting case automatically, and provides per-case pause/resume, cancel, retry and persistent logs without deleting case outputs. The commissioned beam mode uses measured-IDD discrete spectra, Fermi-Eyges BiGaussian emittance, DICOM VSAD spot-axis projection and energy-dependent number-per-MU. It selects a unique machine profile by the RTPLAN `TreatmentMachineName`; profile, NF(E), output correction and hashes are bound in that machine's `particle_calibration.json`. After a commissioned TOPAS run, an immutable source binary plus a calibration audit records the machine/profile fingerprints, `N_plan`, `N_sim`, their scale and the exact spot-allocation snapshot. Line dose, English depth/X/Y CSV/plots, Gamma and MC RTDOSE export all consume that same scale exactly once. Raw and legacy TPS-peak-fit views remain explicitly diagnostic. Results are stored in a standardized per-patient/per-plan cache under `analysis/`. The complete operating procedure, protocol and limitations are documented in [WORKFLOW.md](./WORKFLOW.md).

Current case status is tracked in [PROJECT_STATUS.md](./PROJECT_STATUS.md). As of 2026-08-22, no transport is running; the 100,000-history commissioned result has been particle-calibrated and reprocessed, and its research 3%/3 mm global Gamma pass rate at a 10% TPS threshold is 99.9640%. The 2026-08-21 transport reproduced the preceding run bit-for-bit (same seed and thread count), so the cached Gamma, profiles and MC RTDOSE remain valid for the current production binary — change the seed or the history count before launching another run. Engineering and performance issues are tracked separately in [OPTIMIZATION_REPORT.md](./OPTIMIZATION_REPORT.md). Historical water-phantom outputs remain isolated under `archive/` and are not auto-selected by the GUI.

A separate command-line channel validates one commissioned energy as a single spot in a uniform water phantom, without importing a TPS plan and without building the three-dimensional dose grid. Because it uses a single Geant4 run and three strictly one-dimensional scorers, it affords a much finer sampling step than the full-plan QA, and it exports IDD/PDD curves, R100/R90/R80/R50/R20 range metrics, distal falloff and lateral profile widths for comparison against TPS or measured data. It runs the same commissioned beam model as the full plan. See [WORKFLOW.md](./WORKFLOW.md) section 10; the entry points are `scripts/16_generate_water_phantom_spot.py` and `scripts/17_run_water_phantom_spot.py`.

> Thread guidance: the requested TOPAS thread count is capped at this machine's logical core count. On the 15-core machine used for the current results, requesting 64 threads ran 1.4–2.1x *slower* than requesting 4. Since 2026-08-22 both the GUI presets and the custom-threads field respect this — the browser rejects an over-subscribed value and the backend clamps anything that still reaches it, including retried batch-queue snapshots. The optimal count within 4–15 has not been measured yet.

> Current supported research scope: one HFS carbon-ion PBS beam, gantry 90°, couch/pitch/roll 0°, an axis-aligned regular RTDOSE grid, and either an axis-aligned rectangular 0-HU water phantom or an axial DICOM CT patient. The imported commissioned beam profile is accepted only for an exact treatment-machine name and compatible VSAD. Patient CT still uses a generic TOPAS Schneider HU-to-material table. Particle-number calibration is an independent research physical-dose estimate, not proof of clinical absolute-dose accuracy or acceptance.
